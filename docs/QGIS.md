# Правка сети дорожек, лифтов и щитов воды в QGIS

Все редактируемые слои лежат в одном файле **`data/qgis/flamenca.gpkg`**. Навигатор собирается из него командой `python tools/build.py`.

## Открыть

1. Скачайте репозиторий: **Code → Download ZIP** или `git clone`.
2. В QGIS 3.28+ перетащите в окно `data/qgis/flamenca.gpkg` и в появившемся диалоге отметьте все слои. Стили, подписи и выпадающие списки атрибутов загрузятся из файла сами.
3. Перетащите подложку `source/master.jpg`. Рядом с ней лежат `master.jgw` и `master.jpg.aux.xml`, поэтому план встанет точно под слои. Если QGIS спросит систему координат, выберите ту же, что у слоёв: *Flamenca plan (metres)*.

Координаты — «метры плана», а не GPS: X = пиксель × 0,1, Y = −пиксель × 0,1. Привязку к местности для геолокации делаем отдельно, правки дорожек от неё не зависят.

## Слои

| Слой | Тип | Что править |
|---|---|---|
| `paths` | линии | сеть пешеходных дорожек — по ней строится маршрут |
| `stairs` | точки | лестницы; `id` вида `15-E1` не меняйте — на него ссылаются квартиры |
| `starts` | точки | точки «Откуда»: `id` и названия `name_es/en/fr/ru` |
| `lifts` | точки | лифты (сейчас пусто) |
| `water_panels` | точки | щиты воды (сейчас пусто) |
| `stacks` | полигоны | стояки квартир, только для справки — изменения в навигатор не попадают |

## Сеть дорожек (`paths`)

Сейчас в слое автосеть: около 10 тыс. коротких отрезков, полученных из скелета проходимых зон плана. Она связная, и маршруты от всех входов до всех 25 лестниц строятся. Но местами она идёт по газону, через воображаемые проходы или «лесенкой».

### Перед правкой

- **Прилипание:** *Проект → Параметры прилипания* — включить, «Все слои», вершины и сегменты, допуск 1 м.
- **Топологическое редактирование:** включите его там же, чтобы при перемещении общей вершины двигались все линии, которые в ней сходятся.
- **Режим редактирования:** слой `paths` → кнопка «Редактирование» (карандаш).

### Как править

- **Лишний проход** (через газон, сквозь здание): выделите отрезки и удалите их или поставьте `access = closed`. Закрытые отрезки остаются в файле, но не участвуют в маршрутах — так удобно помечать калитки.
- **Нет прохода:** нарисуйте линию «Добавить линейный объект» от вершины до вершины существующих дорожек. Начало и конец должны прилипнуть к вершинам или сегментам.
- **Атрибуты** (необязательно): `kind` (footpath, gallery, crossing, road, ramp, steps), `steps` = 1 там, где есть ступени, `note` — комментарий.
- **Упростить «лесенку»:** выделите кусок → *Обработка → Упростить* (порог 0,3–0,5 м) или перерисуйте участок заново.
- **Перерисовать участок начисто:** удалите отрезки автосети в нужной зоне и нарисуйте одну аккуратную линию по оси дорожки.

### Правила, чтобы маршрут не ломался

- **Развилка — общая вершина.** Линии, которые просто пересекаются без общей вершины, маршрутизатор не соединит. Исключение: висячий конец ближе 2 м к другой линии сборка пришьёт сама.
- **Лестница и точка старта** привязываются к ближайшей вершине сети. Если лестница далеко от дорожек, дорисуйте к ней короткий отрезок.

### Проверить

- **Висячие концы:** плагин **Topology Checker**, правила *must not have dangles* и *must not have duplicates*.
- **Маршрут, как его построит навигатор:** *Обработка → Анализ сетей → Кратчайший путь (точка к точке)* на слое `paths`.
- **Проверка всех маршрутов разом** после сборки:
  ```bash
  python tools/build.py
  python tools/check_routes.py   # от каждой точки старта до каждой лестницы; ошибка, если что-то недостижимо
  ```

## Лифты (`lifts`)

Удалите служебную точку `EXAMPLE` — она стоит за пределами плана — и ставьте лифты у лестничных ядер.

| Поле | Пример | Зачем |
|---|---|---|
| `id` | `L-15-1` | показывается в карточке квартиры |
| `block` | `15` | |
| `stair_id` | `15-E1` | лифт обслуживает все квартиры этой лестницы |
| `floors` | `0-3` | |
| `serves` | `449 443 437` | только если лифт обслуживает не всю лестницу; номера через пробел или запятую |
| `note` | `llave en conserjería` | показывается в карточке |

Когда в слое есть хотя бы один лифт, навигатор перестаёт рисовать условные лифты у лестниц и показывает настоящие.

## Щиты воды (`water_panels`)

| Поле | Пример |
|---|---|
| `id` | `W-15-3-1` |
| `block`, `floor` | `15`, `3` |
| `place` | `galería`, `portal`, `escalera`, `sótano`, `exterior` (список) |
| `serves` | `449 443` — номера квартир, чьи счётчики или краны в этом щите |
| `kind` | `contadores`, `llave de corte`, `ambos` (список) |
| `photo` | путь к фото (для QField) |

Щит показывается в карточке квартиры, номер которой есть в его `serves`, и отдельным слоем в режиме Pro.

## В поле: QField

Чтобы собирать лифты и щиты на месте, установите на телефон **QField** и передайте туда проект: плагин **QFieldSync** или просто скопируйте `flamenca.gpkg` и `master.jpg` с его файлами. Точки ставьте по подложке. Пока план не привязан к местности, GPS-позиция в этом проекте не отображается.

## Сохранить в навигатор

```bash
python tools/build.py          # пересобирает data/plan-data.js и export/*
python tools/check_routes.py
git add data/qgis/flamenca.gpkg data/plan-data.js export/
git commit -m "Правка дорожек"
git push
```

Без Python можно просто прислать мне исправленный `flamenca.gpkg` — соберу и выложу сам.

## Пересоздать файл с нуля

`python tools/qgis_export.py` создаёт `flamenca.gpkg` заново из автосети. **Ваши правки при этом пропадут.** Нужны библиотеки `pyogrio`, `shapely`, `numpy`. Для обычной сборки (`build.py`) достаточно стандартного Python.
